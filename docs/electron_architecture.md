# Electron Architecture

The Electron app provides the desktop UI, manages backend services as child processes, and handles auto-updates.

## Main Process (`src/main/`)

### `index.ts` — Application Entry

**Responsibilities:**

- Creates `BrowserWindow` with React renderer (Vite dev or production build)
- System tray for background operation (minimize to tray instead of closing)
- IPC handlers for all renderer operations:
  - File dialogs (`dialog:selectAudio`)
  - Backend status (`backend:status`)
  - Service management (`services:stop`, `services:restart`, `service:stop`, `service:restart`)
  - App info (`app:version`, `app:name`, `app:readme`, `app:guide`)
  - Config CRUD (`config:get`, `config:save`, `config:check`, `config:getWithSources`)
  - Config export/import (`config:export`, `config:import`)
  - UI state persistence (`ui-state:get`, `ui-state:save`)
  - Log management (`logs:get`, `logs:clear`)
  - Agent config (`agent-config:get`, `agent-config:save`, `agent-config:restore-defaults`)
  - Storage usage (`storage:usage`)
  - Performance metrics (`metrics:getAll`, `metrics:getPerJobPerformance`)
  - Auto-update (`auto-update:*`)
  - DeepSeek balance (`api:checkDeepSeekBalance`)
  - Aggregate token usage (`api:getAggregateUsage`)
- `.env` loading into `process.env` before any child process spawns
- Context menu (right-click: Copy, Select All, etc.)
- Loads appearance settings via IPC

### `preload.ts` — Context Bridge

Exposes a safe `window.electronAPI` object to the renderer via `contextBridge.exposeInMainWorld`. All methods use `ipcRenderer.invoke()` for type-safe, async communication. Key methods include:

- `getAppVersion()`, `getAppName()`, `getReadme()`, `getGuide()` — app info and documentation
- `getConfig()`, `saveConfig()`, `getConfigWithSources()`, `clearConfig()` — configuration CRUD
- `getAgentConfig()`, `saveAgentConfig()`, `restoreAgentDefaults()` — agent config CRUD
- `getUpdateStatus()`, `checkForUpdates()`, `downloadUpdate()`, `installUpdate()` — auto-update lifecycle
- `getBackendStatus()`, `stopService()`, `restartService()` — service management
- `checkOllamaHealth()`, `startOllamaServer()`, `stopOllamaServer()` — Ollama lifecycle
- `checkDeepSeekBalance()`, `getAggregateUsage()` — API credit + token queries
- `getStorageUsage()` — disk usage breakdown
- `getMetricsAll()`, `getPerJobPerformance()` — performance metrics
- `checkServers()` — batch service health check
- `onNotification()`, `onNotificationClick()`, `onJobStarted()` — event listeners
- `onLogEntry()` — real-time log streaming
- `exportConfig()`, `importConfig()` — config export/import
- `getDefaultUserConfig()`, `restoreDefaultUserConfig()`, `setDefaultConfig()` — user config defaults snapshot/restore/save-current-as-defaults
- `getUiState()`, `saveUiState()` — UI state persistence (userData/ui-state.json)
- `getPathForFile(file)` — absolute filesystem path of a renderer File object (New-form file persistence)
  No `nodeIntegration` — security through context isolation.

### `backend-manager.ts` — Child Process Management

**Spawns three services:**

1. Python Backend (`python3 main.py` on port `:5001`)
2. Bridge Server (`node index.js` on port `:5010`)
3. Agent Runner (`node index.js` — no port, fs.watch based)

**Platform awareness:**

- Detects Windows vs Unix for:
  - Python binary name (`python` vs `python3`)
  - Node.js binary name (`node.exe` vs `node`)
  - Process termination (`SIGTERM` vs `taskkill /F /PID`)
  - Path resolution (bundled binaries / embedded runtime in production)

**Production mode (packaged):**

- The bridge server, agent runner, and bot test scripts run on **Electron's own embedded Node**
  (`process.execPath` + `ELECTRON_RUN_AS_NODE=1`) — no standalone `node.exe` is spawned. This is
  Wine/CrossOver-safe because the app itself already runs under Electron there (a bundled `node.exe`
  fails to launch under CrossOver/Wine with `rc=768` for every version tested: 20.18, 22.23, 24.19).
- Uses bundled resources from `extraResources`:
  - `python-backend/` — standalone Python binary
  - `bridge-server/` + `agent-runner/` — Node.js source with dependencies
  - `agent-config/` — pipeline steps, tool definitions, system prompt
  - `version.json` — build version metadata
- Dev mode resolves Node via the system PATH (`node`/`node.exe`).

**Health monitoring:**

- Polls each service via HTTP health endpoint
- Restarts crashed services automatically
- Tracks child process PIDs for cleanup

### `auto-updater.ts` — Update System

See [Install/Uninstall/Update (Windows & macOS)](windows_install_uninstall_update.md) for full details.

**Two modes:**

- **Dev mode** (`app.isPackaged === false`): git fetch → pull → install deps → rebuild → relaunch
- **Packaged mode** (`app.isPackaged === true`): electron-updater checks GitHub Releases

**IPC channels:**

- `auto-update:status` — returns full update state
- `auto-update:check` — triggers immediate check
- `auto-update:setEnabled` — enable/disable auto-check
- `auto-update:download` — download available update
- `auto-update:install` — install and restart

### `config.ts` — App Configuration

- Reads/writes `config.json` in the user data directory
- Hardcoded defaults for all values
- REQUIRED_CONFIG_KEYS: `["DEEPSEEK_API_KEY"]`
- `getChildEnv()` — generates environment variables for child processes from config
- Tracks config value sources (user_config vs default)

### `ui-state.ts` — UI State Persistence

- Reads/writes `ui-state.json` in the user data directory — see [UI State Persistence](ui_state_persistence.md)
- Stores panel tabs, subtabs, filters, selections, and the New-form draft across restarts
- Renderer is the single writer: loads the whole object once, mutates in memory, saves on a debounce + window close
- Deliberately separate from `config.json` — `config:save` restarts the agent runner and its schema is flat-string / `DEFAULTS`-filtered

### `logger.ts` — Logging System

- Ring buffer: last 50,000 entries in memory
- Per-job log files: `storage/<job_id>/pipeline.log`
- Auto-detects pipeline end markers to close job log streams
- Sub-source extraction from `[tag]` prefixes in log messages
- Subscriber pattern for real-time log streaming to renderer
- Diagnostic plain-text logs: `userData/logs/bridge.log` + `agent.log`
  (bridge stdout/stderr + agent stderr) — written even when the setup modal blocks the Live Log UI
  (post-mortem visibility, esp. under Wine)

### `cleanup.ts` — Uninstall

- Removes user data directory
- Removes Ollama if auto-installed (sentinel file check)
- Removes ffmpeg if auto-installed
- Cross-platform: macOS, Windows, Linux

### State Management

No external state library — uses React hooks and prop drilling:

- `useApi()` — bridge server communication
- `useUiState()` / `useUiStateValue(path, fallback)` — persisted UI preferences (userData/ui-state.json)
- `useJobStatus(jobId, fetcher, backendHealthy)` — polling with 30-minute timeout, backend-down resilience
- `useServerStatus()` — periodic health checks for Python, Bridge, Agent, diarization, and Ollama
- `useForeignJobs()` — detects bot-created jobs running outside the UI

### Key UI Features

- **Drag-and-drop upload** with file type validation
- **Attendee autocomplete** from localStorage with registered attendee lookup and conflict detection
- **Skip steps** — toggle non-essential pipeline steps on upload
- **Pipeline progress stepper** — multi-stage visual progress (up to 11 stages with approval gates), per-stage status with friendly labels
- **Collapsible Mini Live Log** under the pipeline stepper — real-time log entries color-coded by source
- **Approval Gates** — Gate 1 (raw transcript review) and Gate 2 (delivery review) modals with edit, approve, and reject-with-retry
- **Speaker labeling modal** — appears when speaker count doesn't match attendee count, with playable audio clips, per-speaker conflict detection, and voice-match verification
- **Tabbed results** — 8 top-level tabs (Pipeline, Transcript, Summary, Analysis, Attendees, Delivery, Audio) with Developer group containing 4 sub-tabs (Tokens, Performance, Config, Logs)
- **Config export/import** — JSON file with agent config snapshot; import blocked during active jobs
- **Config-required overlay** — full-screen blocker when API keys are missing
- **Tabbed About panel** — About tab (version + README) and Guide tab (searchable end-user guide with table of contents navigation)
- **Live log viewer** — filterable by source, sub-source, and level, with text search, auto-scroll, and persisting filters
- **Persistent UI preferences** — panel tabs, filters, selections, and the New-form draft survive app restarts via `userData/ui-state.json` (see [UI State Persistence](ui_state_persistence.md))
- **Performance monitoring** — SVG chart of CPU/memory with pipeline stage markers
- **Ollama management** — start/stop/restart controls directly from StatusBar
